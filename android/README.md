# gust for Android (APK)

The installable PWA at <https://refcell.github.io/gust/> is the primary app. This directory builds an
optional Android APK: a [Trusted Web Activity](https://developer.chrome.com/docs/android/trusted-web-activity)
(TWA) generated by [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) that opens
`https://refcell.github.io/gust/app/?source=pwa` in Chrome.

| | |
| --- | --- |
| Package ID | `io.github.refcell.gust` |
| Web manifest | <https://refcell.github.io/gust/manifest.webmanifest> |
| Scope | `https://refcell.github.io/gust/` |
| Features | notification delegation, location delegation |
| Download | <https://github.com/refcell/gust/releases/download/apk-latest/app-release-signed.apk> |

## Files

- `twa-manifest.json`: checked-in Bubblewrap config. Edit this to change name, colors, icons, or
  features. The Gradle project is not committed. It is regenerated from this file on every build.
- `build-apk.sh`: non-interactive build (`bubblewrap update` + `bubblewrap build`), signing, and
  Digital Asset Links output. Writes everything to `android/build/` (gitignored).
- `../.github/workflows/android.yml`: CI that runs the script and publishes a GitHub Release.

## CI

`.github/workflows/android.yml` runs on:

- push of a `v*` tag: creates or updates the release for that tag.
- push to `main` that changes `android/**` or the workflow, and manual `workflow_dispatch`: moves
  the `apk-latest` tag to the commit and updates the rolling `apk-latest` prerelease.

Each run uploads `app-release-signed.apk` and `assetlinks.json` to the release. It also uploads them,
with `app-release-bundle.aab` and `sha256.txt`, as the `gust-apk` workflow artifact. The SHA-256
signing certificate fingerprint and the generated `assetlinks.json` appear in the job summary.
`versionCode` is `github.run_number`, so it always goes up. `versionName` is the tag without the `v`,
or `1.0.<run_number>`.

### How it stays non-interactive

These behaviors were checked against the `@bubblewrap/cli@1.27.0` source:

- JDK 17 comes from `actions/setup-java`. The Android SDK comes from `android-actions/setup-android`,
  with `build-tools;36.1.0` (the version Bubblewrap 1.27.0 needs) and `platforms;android-36`
  preinstalled. If build-tools were missing, Bubblewrap would try to install them through sdkmanager.
- The Bubblewrap config (`jdkPath`, `androidSdkPath`) is pre-written. Without it, Bubblewrap prompts
  to download a JDK and SDK.
- Bubblewrap requires `$ANDROID_HOME/tools` or `$ANDROID_HOME/bin` to exist. Modern SDKs have neither,
  so the script symlinks `$ANDROID_HOME/bin` to the directory that contains `sdkmanager`.
- `bubblewrap update --skipVersionUpgrade` generates the project and `manifest-checksum.txt`. Because
  the checksum matches, `bubblewrap build` does not ask whether to regenerate.
- `bubblewrap build` reads `BUBBLEWRAP_KEYSTORE_PASSWORD` and `BUBBLEWRAP_KEY_PASSWORD` from the
  environment instead of prompting. `--skipPwaValidation` is passed, though 1.27.0's build does not
  validate anyway.

## Signing

When the `ANDROID_KEYSTORE_B64` secret is **not** set, every run generates a throwaway keystore with
`keytool`. That works for a first install. But Android refuses to install an update signed with a
different key, so each new APK means uninstalling the old one first (local app data is lost).

To get updates that install in place, store one stable keystore as repo secrets:

```sh
keytool -genkeypair -keystore gust.keystore -storetype PKCS12 -alias android \
  -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=gust, O=refcell"
base64 < gust.keystore | tr -d "\n" | gh secret set ANDROID_KEYSTORE_B64 -R refcell/gust
gh secret set ANDROID_KEYSTORE_PASSWORD -R refcell/gust     # the store password you chose
# optional: ANDROID_KEY_PASSWORD (defaults to the store password), ANDROID_KEY_ALIAS (defaults to android)
```

Back up `gust.keystore` and its password. If you lose them, you can never ship an in-place update again.

## Digital Asset Links (why the URL bar shows)

A TWA runs full screen with no browser UI only after Chrome verifies that the site trusts the app.
Chrome checks `https://<host>/.well-known/assetlinks.json`, which must list the package ID and its
signing certificate's SHA-256 fingerprint. The host here is `refcell.github.io`, and its root is
**not** served by this repo. `refcell/gust` only publishes `/gust/`, and the `refcell/refcell.github.io`
repo does not exist. So verification fails, and Chrome opens the app as a Custom Tab with a thin URL
bar. Everything still works: location, notifications, offline. The bar just stays visible.

Two ways to fix it. Both need a stable signing key (see above), because the fingerprint has to stay
the same:

1. **Create `refcell/refcell.github.io`** (a user Pages site) and commit the `assetlinks.json` from a
   release to `.well-known/assetlinks.json`. Add an empty `.nojekyll` so Jekyll does not drop the dot
   directory. The file then serves at `https://refcell.github.io/.well-known/assetlinks.json`.
2. **Use a custom domain** for gust (for example `gust.example.com` via a Pages `CNAME`). Serve
   `/.well-known/assetlinks.json` from this repo's `public/`. Change `host` (and the URLs) in
   `twa-manifest.json` to match.

To check: `adb shell pm get-app-links io.github.refcell.gust`, or use Google's
[Statement List tester](https://developers.google.com/digital-asset-links/tools/generator).

## Building locally

You need Node 18+, JDK 17 (`JAVA_HOME`), and an Android SDK (`ANDROID_HOME`) with
`build-tools;36.1.0` and `platforms;android-36` installed and licenses accepted:

```sh
./android/build-apk.sh
adb install android/build/out/app-release-signed.apk
```

Set `ANDROID_KEYSTORE_B64` and `ANDROID_KEYSTORE_PASSWORD` to sign with your stable key.

## Upgrading Bubblewrap

Bump `BUBBLEWRAP_VERSION` in `build-apk.sh`. Then update `BUILD_TOOLS_VERSION` there and the
`build-tools;…` package in the workflow to match `BUILD_TOOLS_VERSION` in
`@bubblewrap/core/dist/lib/androidSdk/AndroidSdkTools.js` for that version. Raise
`platforms;android-NN` if the generated project's `compileSdkVersion` changes.
